- Status: Implemented

- Workstream: W1
- Roadmap: [`0000-the-roadmap.md`](0000-the-roadmap.md)
- Source of truth: [`protocol_spec.md`](../protocol_spec.md)

This plan is the W1 breakdown. It implements the NETH ERC-20 in spec §4 and the mint-authority lock required by §18.3. It does not implement Grave, era math, Reaper, or harvest.

## 1. Purpose

Ship `contracts/src/NETH.sol` as a separate, immutable ERC-20 so W2 (Grave) and W3 (Reaper) have a real token to mint and burn. Lock minting to a single Grave address after deploy, with no standing admin mint.

## 2. Scope

In scope:

- `NETH` as OpenZeppelin Contracts 5.x `ERC20` + `ERC20Burnable`
- name `Nether`, symbol `NETH`, 18 decimals
- `mint` callable only by the locked Grave address
- one-time Grave mint-authority wiring that then becomes immutable
- unit and fuzz tests required by spec §17 for mint authorization, burn behavior, and “no admin path can mint NETH”
- replace the W0 `test/unit/Scaffold.t.sol` compile smoke test

Out of scope:

- `Grave`, `EraMath`, `bury()`, reckoning, `EraCompleted`
- Reaper auctions or Reaper-specific burn accounting (`totalNethReaped` is W3)
- protocol views in spec §12 except what ERC-20 already provides (`totalSupply`, `balanceOf`, …)
- harvest, strategy adapter, pause, timelock, Ownable/AccessControl on NETH
- deploy scripts (W6), frontend (W7), keeper (W8)
- accepting NDR-0002
- proxies, upgradeability, `ERC20Pausable`, `ERC20Permit`, `ERC20Votes`, `ERC20Capped`, transfer taxes, rebase, blacklist

Do not unite W1 and W2 into one contract ([`NIP-0000`](0000-the-roadmap.md) §2).

## 3. Mint authority

Spec §4.1: mint is callable exclusively by the immutable Grave. Spec §10.1: no admin mint. Spec §18.3 production sequence is: deploy NETH, deploy Grave, then finalize Grave-only mint authority.

[`NIP-0000`](0000-the-roadmap.md) already allows constructor, a one-time setter that then becomes immutable, or equivalent. This NIP picks the setter because it matches that named finalize step without CREATE2, and W1 tests can lock a stub before Grave exists.

### 3.1 Mechanism

1. Constructor takes `graveSetter`, the only account that may call `setGrave`. Reject `address(0)`.
2. `grave` starts at `address(0)`. `mint` reverts until `setGrave` succeeds.
3. `setGrave(address grave_)` may be called once, only by `graveSetter`. `grave_` must be a non-zero contract (`extcodesize > 0`). On success, store `grave` and zero `graveSetter`.
4. After that, `grave` is never written again. There is no owner, minter role, or other standing privilege on NETH.
5. `mint(address to, uint256 amount)` succeeds only when `msg.sender == grave`. It calls OpenZeppelin `_mint`. No constructor mint. `totalSupply()` is 0 until Grave mints.

This is setup authority already listed in NIP-0000 §5, not monetary upgradeability.

### 3.2 Why not the other authorized shapes

| Shape | Why not for W1 |
|---|---|
| Grave address in NETH constructor | Requires Grave’s address at NETH deploy. Spec §18.3 deploys NETH first. Needs CREATE2/CREATE3, which is a W6 concern. |
| Ownable / `AccessControl` mint | Looks like admin mint. Spec forbids a standing admin mint. Ownable2Step belongs to W4 strategy admin, not NETH ([`NIP-0001`](0001-scaffolding.md) §5). |
| CREATE2 predicted Grave in constructor | Equivalent for W6 if someone later wants bytecode with `grave` immutable from construction. That would change this contract’s API; do not mix it into W1. |

W6 still calls `setGrave(grave)` as spec §18.3 step 10, then checks `neth.grave() == grave`, `neth.graveSetter() == address(0)`, and `neth.totalSupply() == 0`.

## 4. Contract surface

File: `contracts/src/NETH.sol`.

```text
pragma solidity 0.8.36;

constructor(address graveSetter_)
name() → "Nether"
symbol() → "NETH"
decimals() → 18                    // OpenZeppelin ERC-20 default; do not override unless tests fail
grave() → address                  // mint authority; address(0) until setGrave
graveSetter() → address            // address(0) after setGrave
setGrave(address grave_)           // one-time
mint(address to, uint256 amount)   // only grave
burn(uint256 amount)               // ERC20Burnable; holder or Reaper burns own balance
burnFrom(address account, uint256 amount)
```

Plus the ordinary ERC-20 surface (`transfer`, `approve`, `transferFrom`, `allowance`, `totalSupply`, `balanceOf`, `Transfer`, `Approval`).

Use custom errors (spec §18.2). Suggested names, not a protocol requirement:

```text
ZeroAddress()
NotGraveSetter()
GraveAlreadySet()
NotGrave()
NotContract()
```

Emit `GraveSet(address indexed grave)` from `setGrave`. Spec §13 does not list it; it is a one-time lock log for W6 post-deploy checks and later privileged-role alerts (§19). Do not add other custom events.

`totalNethMinted` and `totalNethReaped` stay off this contract. After Reaper burns, `totalSupply()` is not gross issuance (§4.2). W2 can count burial issuance; W3 can count Reaper burns. Holder `burn` is allowed (§11 “holder/Reaper burn”) and must not be attributed as reaping.

## 5. What NETH must not do

These are spec §4.1, §10, and §20 constraints, not optional extras:

- no transfer tax, reflection, rebase, or fee-on-transfer
- no blacklist or whitelist
- no pause on ordinary transfers (`ERC20Pausable` is forbidden here; W4 pause is strategy-sensitive operations only)
- no admin mint and no mint to the deployer
- no admin burn of third-party balances (`burnFrom` only with allowance)
- no fixed cap (`ERC20Capped` would invent a maximum supply; §4.2 has none)
- no `ERC20Permit`, votes, snapshots, or wrapping
- no proxy, UUPS, Beacon, or upgradeable OpenZeppelin modules
- no NETH price oracle, DEX hook, or strategy call
- no ETH receive/mint path (burial is Grave `bury()` in W2)

## 6. Tree

Follow [`NIP-0001`](0001-scaffolding.md). Production token is one file; tests live under the reserved unit/fuzz/mocks directories.

```
contracts/
├── src/
│   └── NETH.sol
└── test/
    ├── unit/
    │   └── NETH.t.sol          replaces Scaffold.t.sol
    ├── fuzz/
    │   └── NETH.t.sol
    └── mocks/
        └── GraveStub.sol
```

`GraveStub` is a test helper that holds `NETH` and exposes a function that calls `neth.mint`. It is not the W2 Grave, not a strategy, and must not be deployed in production. Keep it under `test/mocks/`.

Do not add `src/interfaces/INETH.sol` in this slice. W2 imports `NETH.sol`. An interface is a later §22 artifact if W6/docs need one.

## 7. Tests

Spec §17: tests that introduce the behavior ship with the slice. W1 does not run era, harvest, auction, fork, or protocol-wide invariant suites (those start W2+ / W4+ / W5+ per NIP-0001).

### 7.1 Unit (`test/unit/NETH.t.sol`)

- `name`, `symbol`, `decimals` match §4.1
- `totalSupply() == 0` and `grave() == address(0)` before `setGrave`
- `mint` reverts before `setGrave`, from the setter, from a random EOA, and from a contract that is not `grave`
- `setGrave` reverts for `address(0)`, an EOA, a second call, and a caller other than `graveSetter`
- after `setGrave`, `graveSetter() == address(0)` and `GraveSet` was emitted
- stub `grave` can mint; balances and `totalSupply` increase by the minted amount; `Transfer(address(0), to, amount)` is emitted
- minting does not take an admin path (no `onlyOwner`, no role grant)
- holder `burn` decreases balance and supply; Reaper-style use is “stub holds NETH, then `burn`”
- `burnFrom` works with allowance and reverts without it (no admin burn of third-party balances)
- ordinary `transfer` / `approve` / `transferFrom` work and do not mint
- no `pause` / `unpause` / blacklist functions exist (use a compile-time or `staticcall` absence check, not a comment)

### 7.2 Fuzz / property (`test/fuzz/NETH.t.sol`)

Include the §17 properties that apply before Grave exists:

```text
no admin path can mint NETH
only grave can mint (after setGrave)
setGrave succeeds at most once
burn cannot increase supply
transfer / transferFrom / approve never change totalSupply
```

Assume callers, recipients, and amounts. After lock, for any `msg.sender != grave`, `mint` reverts and `totalSupply` is unchanged. The setter account cannot mint. Direct `deal` of NETH in tests is not an admin path; do not use it to “prove” mint.

Do not assert `total NETH minted == deterministic burial issuance` here; that needs W2 era math.

### 7.3 Not in W1

- era formulas, `minNethOut`, principal monotonicity
- stateful protocol invariants (W2+/W4+)
- Base fork tests (W5+/W6)
- deploy-script abort checks (W6)

Existing CI (`.github/workflows/contracts.yml`) already runs `forge fmt --check`, `forge build --sizes`, and `forge test -vvv` from `contracts/`. Do not add a second workflow.

## 8. Implementation steps

Do not run these until this NIP is explicitly started.

1. Add `contracts/src/NETH.sol` as in §4, inheriting OpenZeppelin `ERC20` and `ERC20Burnable` from `@openzeppelin/contracts/` (NIP-0001 remapping). `pragma solidity 0.8.36;`. SPDX `UNLICENSED` ([NDR-0004](../ndr/0004-source-available-until-mainnet.md)).

4. Do not change `foundry.toml`, remappings, OpenZeppelin/forge-std pins, or CI versions.
5. From `contracts/`: `forge fmt`, `forge build`, `forge test`.

## 9. Acceptance criteria

W1 is done when:

- `NETH` is a separate production contract under `contracts/src/NETH.sol`, not merged into Grave
- metadata is Nether / NETH / 18
- only the address locked by `setGrave` can mint; that lock is one-shot; setter privilege is gone afterward
- holders (and later the Reaper) burn with `ERC20Burnable`; there is no admin burn of others’ balances
- ordinary transfers are not paused and have no tax, rebase, or blacklist
- `forge fmt --check`, `forge build`, and `forge test` pass from `contracts/`
- no Grave/Reaper/era/harvest logic, no proxy libraries, no deploy scripts
- NDR-0002 is still Proposed unless it is explicitly accepted in a later change
